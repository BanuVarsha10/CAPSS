# Metadata Inventory – AMF Log Analysis

**Source File:** `logging/raw_logs/amf.log`

## Overview

This metadata inventory identifies the useful metadata present in the AMF log generated by Open5GS during UE registration and authentication. These fields are extracted by `parse_amf_logs.py` to generate a structured dataset for privacy analysis, privacy scoring, correlation analysis, and metadata minimization.

| Metadata Field | Present | Example | Purpose |
|---------------|---------|---------|---------|
| Timestamp | ✅ Yes | `07/01 13:26:51.010` | Order registration events and measure timing |
| Log Level | ✅ Yes | `INFO`, `WARNING` | Indicates event severity |
| AMF Module | ✅ Yes | `amf`, `gmm`, `ngap`, `sbi`, `metrics` | Identifies the Open5GS component generating the log |
| Event Type | ✅ Yes | `InitialUEMessage`, `Registration complete` | Tracks the registration workflow |
| SUCI | ✅ Yes | `suci-0-999-70-0000-0-0-0000000001` | Concealed subscriber identifier used during registration |
| SUPI / IMSI | ✅ Yes | `imsi-999700000000001` | Permanent subscriber identity |
| Authentication Result | ✅ Yes | `Authentication failure [21]` | Authentication failures are explicitly logged. Successful authentication is inferred from successful registration. |
| Registration Status | ✅ Yes | `Registration complete` | Indicates successful UE registration |
| gNB Connection | ✅ Yes | `gNB-N2 accepted` | Indicates successful connection between gNB and AMF |
| gNB IP Address | ✅ Yes | `192.168.56.102` | Network node information |
| DNN | ✅ Yes | `internet` | Requested Data Network Name |
| S-NSSAI | ✅ Yes | `SST:1 SD:0xffffff` | Requested network slice |
| Session Management Context | ✅ Yes | `smContextRef`, `smContextResourceURI` | Session management information |
| PDU Session Events | ✅ Yes | `/nsmf-pdusession/...` | PDU session establishment and management |
| Warning/Error Messages | ✅ Yes | `Authentication failure`, `Retry registration with NRF` | Detect abnormal behaviour |

# Important Registration Events Observed

## gNB Connected

Example:

```
gNB-N2 accepted [192.168.56.102]
```

Purpose:

- Indicates successful gNB connection to the AMF.

---

## Initial UE Registration

Example:

```
InitialUEMessage
```

Purpose:

- Marks the beginning of the UE registration procedure.

---

## Unknown UE by SUCI

Example:

```
Unknown UE by SUCI
```

Purpose:

- Indicates that the AMF received a concealed subscriber identity (SUCI) and is resolving it to the corresponding subscriber.

---

## Authentication

Observed Examples:

```
Authentication failure [21]
Authentication failure (Synch failure)
```

Purpose:

- Records authentication failures and their associated failure reasons.

**Note**

- Authentication failures are explicitly logged.
- Successful authentication is **not explicitly logged** in the AMF log.
- Successful authentication is inferred from the subsequent **Registration complete** event.

---

## Registration Complete

Example:

```
[imsi-999700000000001] Registration complete
```

Purpose:

- Indicates successful completion of the UE registration procedure.

---

## Subscriber Information

Example:

```
UE SUPI[imsi-999700000000001]
DNN[internet]
S_NSSAI[SST:1 SD:0xffffff]
```

Purpose:

- Provides subscriber identity and requested network configuration.

---

## Session Management

Examples:

```
smContextRef
smContextResourceURI
/nsmf-pdusession/
```

Purpose:

- Records PDU session establishment and session management information.
